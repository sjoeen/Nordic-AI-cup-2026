## 1. Wire contract (VERIFIED against dtos.py, api.py, utils.py, local_evaluator.py)

| Item | Requirement | Source |
| --- | --- | --- |
| Route | `POST /predict`, port 9054, `api.py` unchanged | `api.predict_endpoint` |
| Request | `audio_base64` (plain base64 MP3), `audio_filename` (metadata), `questions` (list[str]) | `ASRQuestionRequestDto` |
| Response | `answers: list[bool]`, `evidence_start: list[float|null]`, `evidence_end: list[float|null]`, equal lengths, positional | `ASRQuestionResponseDto.evidence_matches_answers`, `utils.validate_response` |
| False answers | both timestamps null (enforced by `response_checks.finalize`) | README, plan §5.3 |
| True with nulls | legal; scores 0 tIoU | README |
| Interval validity on the service | both finite numbers, `end >= start`; else scores 0 silently | `utils.evidence_interval` |
| Per-request timeout | 60 s; attempt budget 60 s x conversations; 5 consecutive timeouts abort | `local_evaluator` constants |
| Scoring | `0.4 * accuracy + 0.6 * mean tIoU` over all annotated positives | `local_evaluator.Statistics`, `utils.temporal_iou` |

Evaluator traps confirmed in source (plan §6.2) and how they are handled:

1. Aborted local replay drops unsent questions → `eval_tools/replay.py` recomputes with full denominators.
2. `Statistics.record` scores tIoU regardless of the predicted boolean → we still null spans on `False` (never exploit).
3. `utils.audio_duration_seconds` is header-based → `audio_io` uses decoded length for bounds.
4. `example.predict` in the starter decoded audio outside the try → new `example.predict` wraps everything.
5. `validate_response` does not check false/null pairing or bounds → `response_checks.strict_validate` does.
6. `wait_for_endpoint` only checks the root → `Pipeline.warm_up` runs a synthetic request before serving.

## 3. Threat model and boundaries on the inference path

| Boundary | Control | Where |
| --- | --- | --- |
| Base64 / size | strict decode, encoded-length bound before decode, 32 MiB cap, 30 min duration cap | `audio_io.decode_base64_audio`, `decode_request_audio` |
| Filename | logged (truncated) only; never a path, key or feature | `pipeline.predict_with_trace` |
| Transcript / question text | data only; ids and timestamps generated by trusted code; NLI/LLM see text as JSON data fields | `transcript`, `qa_backend`, `qa_llm_backend.build_messages` |
| LLM output | strict JSON parse; bool type check; unit ids filtered against the context; extra keys ignored; one bounded repair | `qa_llm_backend.parse_llm_output` |
| Evidence | only valid unit/word ids map to seconds; clamp to `[0, duration]` | `evidence.select_span` |
| Response | `finalize` + `strict_validate` + wire-JSON check | `response_checks` |
| Tools / network | QA models have no tools; no outbound calls at request time; models loaded from local cache | design; verify with `HF_HUB_OFFLINE=1` in the readiness run |
| Failure containment | per-stage try/except, fallback ladder, emergency response | `pipeline`, `example` |
| Deadline | monotonic `Deadline`; ASR stops consuming segments near the budget; QA degrades to lexical | `asr_backend`, `qa_backend` |

Fixtures: `security_fixtures/transcript_attacks_v1.json` (7 cases, 6 families +
benign control) run by `tests/test_security.py`. Coverage is transcript- and
question-level; audio-level attacks (TTS of injected speech) are not yet
covered. Measured attack success is reported per run in `reports/project_state.md`.

## 3b. Review outcomes (2026-09-18)

Adversarial reviews completed for transcript, asr_backend, audio_io (partial,
FLAC-silence regression landed), qa_llm_backend, evidence, response_checks and
factcheck; qa_backend, question_rewrite and eval_tools were reviewed by the
integrator only. Notable fixes: NaN timestamps serialised as null by pydantic
now rejected by the wire check; `finalize` never raises on hostile items;
false fact-check contradictions on ages, decimal commas, month/week
conversions and spoken ranges removed; quadratic fact-check path made linear
(3000-word window: 63 ms to 32 ms). The pipeline now always runs
`strict_validate` plus a parse of the serialised body before returning and
substitutes the constant emergency response if either fails.

Security fixtures: 7/7 pass with the lexical backend and 7/7 with the real
retrieval+NLI backend (`RUN_SLOW=1`), including false-side answer
expectations.

## 4. Unresolved risks

- Production hardware unknown → latency compliance of `small`/`large-v3` unmeasured there.
- No audio-level adversarial fixtures yet.
- Cooperative cancellation only at segment granularity for ASR and batch granularity for NLI; a single very slow batch cannot be interrupted.
